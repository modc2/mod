write a mod

        
        
        
      

      

        A mod is a folder: a config.json saying what it is, and an anchor —
        mod.py or mod.rs — that runs. The config is a claim and the
        anchor is the fact; verify runs the registry’s own checks over both, and the
        one that matters is kind_matches_anchor: what your anchor defines has to be
        what your config says it is. Nothing is stored until it passes.

have the agent write one

        checking for an agent…
      

      

        The Claude agent on this box is handed the template, the ABI and the check list, and
        answers with a folder. It is then put through the same verifier every upload goes
        through, and — if it passes — loaded in the sandbox and asked to play. A folder that
        fails either gate goes back with the failed checks attached, up to three times.
        Nothing is stored until it passes both. The agent runs with no tools and no MCP
        servers: it can answer, and nothing else.

execute

      

        The module runs in this tab, inside a Worker with no filesystem and no network,
        on a seeded clock and a seeded PRNG. Nothing is sent to the server.
        A module that hangs is terminated — that is what the worker is for.

make a game

      

        A game is a Python class defining four methods, or a wasm module exporting five
        functions. There is nothing to register and nothing to ask permission for: upload it
        and it is a game, because the role is read out of what you uploaded. The same is true
        of a player, which needs one method or one export.
