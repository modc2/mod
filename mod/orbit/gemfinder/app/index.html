How the score works

Type anything in the box at the top and it becomes a theme for that scan: its words are matched against every candidate's name and description (short words like "ai" must stand alone, longer ones may be a prefix, so "robot" also finds robotics), CoinGecko search and the categories those words name, DexScreener search and Yahoo search pull in more candidates, and the theme is heated against the 13 built-in narratives (category move, matched stocks' day move, HN buzz, crowding). Only gems that fit the theme are listed.

Cache. Scans are kept for 10 minutes in the server and the base scan is refreshed in the background, so the page opens from cache instantly; Rescan live hits every feed again. Every feed above is fetched in parallel (raw bodies cached 10 min). Results are merged per ticker, matched to narratives by keywords and category, and each narrative gets a heat from its CoinGecko category move, seed-stock move, Hacker News story count (7d) and how many scanned candidates fall into it. Then each candidate is scored 0-100:

partmaxmeaning
attention30how many independent feeds list it, and how high
velocity20reddit mentions vs 24h ago, 1h volume pace, buy/sell ratio, relative volume
narrative25heat of the hottest theme it belongs to
momentum15rising, but not already vertical (best 0..+60%; above +150% = already mooned)
size10small enough to move (crypto $5M-100M, stocks $300M-2B)
− penaltythin liquidity, no pool, FDV >100x liquidity, pair <24h old, sell pressure, penny stock

It measures attention, not a forecast. Most narrative pumps round-trip and many micro-cap DEX tokens are rugs.

Sign-in. Sign in connects a mod-protocol identity: a browser wallet signs one message (no transaction, no gas), or the box itself mints a token with its local key. Scanning stays open to everyone; identity is for the box's own writes.

For agents (MCP + REST)

This module is also an MCP server — any agent gets the same scanner as tools, keyless and read-only. Full machine-readable docs (every tool schema, every route, how to read a gem) live at GET /docs.
