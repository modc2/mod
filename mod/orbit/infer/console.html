why one binary

A model that has to be converted again on the way to where it runs is a model nobody measured. ONNX is the format both runtimes here execute directly — onnxruntime on the server, onnxruntime-web (wasm, SIMD, threads when the page is cross-origin isolated, WebGPU where it exists) in this tab — so the artifact that was optimized and the artifact that ships are the same file, and the architecture it started as stops mattering: by the time it is here, a ResNet and a transformer are both just graphs.

Two results this module will keep telling you, because they are true and inconvenient: quantization often makes small graphs slower — the dequantize nodes cost more than the narrower weights save — and the all pass produces a binary that cannot leave the machine that made it, because it rewrites the graph into com.microsoft.nchwc.* layout operators for that CPU. Both show up in the report rather than in a footnote.

The neighbouring claim — that every operator onnxruntime invented breaks a browser — is false, and this tab is how that was found out. extended fuses into FusedConv and BiasGelu, which look just as vendor-specific; both load and run here, because the wasm backend registers the contrib domain. So portable gives three answers rather than two, and the static check is only ever a prediction. This is the proof.
