IMPORT A REPL INTO THE FLEET

      

        
Replit blocks anonymous Repl export
          (403), so import goes through the repo behind the Repl: in the Repl open
          Git → connect a GitHub repo, then paste that repo here. The clone lands in
          mod/orbit/<name> and gets a config.json + anchor if it
          has none.

        

          

            

          

            

        

        

          

      

      

    

  


  
  

    

      
What this is
A two-way bridge, not a Replit
        client. It does the things that actually cross the boundary: bundle a module into a
        Repl, address the mods already running on Repls (catalog + call + MCP), browse Replit
        DB, import a Repl's repo.

      
The URL rule
App at /replit,
        API at /api/replit, and a null POST returns this module's
        info — the same three rules every module follows.

      
Writes are local
Bundling, linking, importing
        and DB writes require a loopback request with no X-Forwarded-For. Through
        the gateway this console is read-only.

m replit                          # status
m replit/modules                  # what can be bundled
m replit/bundle git               # package orbit/git for Replit
m replit/zip git                  # …and zip it
m replit/run_url owner/repo       # one-click import URL
m replit/link demo https://x.replit.dev
m replit/catalog                  # the mods on Replit + their fns
m replit/repl demo refresh=1      # one Repl, re-discovered
m replit/call demo info           # call a fn on the Repl
m replit/mcp_tools                # the MCP tool surface
m replit/mcp tools/list           # one JSON-RPC message
m replit/db_set hello world
m replit/import_repl owner/repo
m replit/serve                    # this console + MCP on :50530
